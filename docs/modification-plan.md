# 修改方案（待确认）

本方案统筹以下内容：

- 行为问题审核结论（见 `docs/behavior-review.md`）
- 本轮原型修改意见：账号鉴权、流程视图、取消流程审核侧栏、自适应与对齐

## 三、视觉表达

### V1 流程视图重绘

- **保留**现有流程图的全部业务关系：立项与审核、需求、规格书、I/II/III/IV 类设计分支、开发、冒烟 → 单板 / 长运可选路径 → 测试审核 → 整机测试 → 发布评审 → 归档 → 版本发布 → 结项，以及 ECN/PCN、紧急下发、各处退回路径。
- **节点改为圆形**，节点名放在圆下方。审核节点用较小的菱形或带审核标记的圆加以区分。
- **压缩横向长度**：由现在约 4540px 的单行横向展开，改为按 4 个阶段分段、分行排布。桌面端无需横向滚动；手机端改为纵向排列。
- **节点状态**（规则用 R3）：已完成为实色，当前节点为高亮描边，未到达为灰色（状态数量见待确认 D5）。点击节点进入对应阶段页面，灰色节点按 I4 处理。
- 原图引用的 `assets/lifecycle-flowchart.jpg` 不再使用。重绘后由代码生成流程图，不依赖图片。

### V2 自适应与对齐

放在功能和页面结构改完之后统一做，避免页面结构变化后返工。

- **断点**：桌面 ≥ 1280px，平板 768–1279px，手机 < 768px。
- **应用外框**
  - 平板及以下：侧边栏收起为抽屉，由顶栏菜单按钮打开。
  - 手机：顶栏搜索收起为图标；抽屉和弹窗占满屏幕宽度；表格改为可横向滚动。
- **对齐规则**（统一写在基础样式中，不逐页打补丁）
  - 全站统一 12 列网格、统一间距和页面内边距。
  - 同一行的卡片等高，卡片内容区自动撑满、底部操作对齐。
  - 同一页面上下各行的列宽对齐，左右边缘与页头、Tab 对齐。
  - 列数随宽度递减：4 列 → 2 列 → 1 列。不出现"一大一小"的错位，奇数卡片时最后一张占满整行。
- **核查方式**：每个页面在 1440 / 1024 / 390 三种宽度下截图，逐页列出错位问题后修复；修复后重新截图对比。
